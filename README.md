# DriveSim

## Короткий опис

`DriveSim` — це навчальний проєкт на C, який моделює електропривод електромобіля і надає можливість керування ним через `Modbus TCP`.

Програма:
- запускає симуляцію руху електромобіля з частотою `50 Гц`;
- приймає команду моменту двигуна через `Modbus TCP`;
- дозволяє читати параметри моделі через `Modbus input registers`;
- сигналізує про аварію датчика педалі акселератора (некоректне значення команди) через `Modbus discrete input`;
- містить окремі модульні тести для фізичної моделі автомобіля.

Проєкт орієнтований на студентів і підходить як приклад:
- багатопотокової програми на C;
- простої фізичної симуляції;
- TCP-сервера `Modbus`;
- структури кросплатформового проєкту з `CMake` і тестами.

## Бібліотеки, які використовуються

- `nanoMODBUS`
  Призначення: реалізація протоколу `Modbus`, обробка запитів клієнта, виклик callback-функцій для читання і запису регістрів.

- `tinycsocket`
  Призначення: кросплатформова робота з TCP-сокетами. Використовується для створення `Modbus TCP` сервера, прив'язки до порту, очікування і приймання клієнтів.

- `tinycthread`
  Призначення: кросплатформові потоки і mutex-и за стилем `C11 threads`. Використовується для окремого потоку симуляції та окремого потоку виводу швидкості.

- `Unity`
  Призначення: модульне тестування. Використовується для перевірки фізичної моделі в `tests/VehicleTests.c`.

## Як зібрати і запустити

### Варіант 1: звичайна збірка через CMake

```sh
cmake -S . -B build
cmake --build build
```

Після збірки:
- основна програма: `build/src/DriveSim`
- тести: `build/tests/VehicleTests`

Запуск симулятора:

```sh
./build/src/DriveSim
```

### Варіант 2: збірка через CMake Presets

У проєкті вже є presets у файлі `CMakePresets.json`.

Приклади:

```sh
cmake --preset linux-debug
cmake --build --preset linux-debug
```

Для Windows доступні також:
- `x64-debug`
- `x64-release`
- `x86-debug`
- `x86-release`

Артефакти збірки для preset-ів зберігаються в `out/build/<preset-name>`.

## Як запустити тести

Після збірки можна запустити всі тести через `ctest`:

```sh
ctest --test-dir build --output-on-failure
```

Або напряму виконати тестовий файл:

```sh
./build/tests/VehicleTests
```

Що перевіряють тести:
- коректну ініціалізацію моделі;
- обмеження моменту межами двигуна;
- зміну швидкості і шляху після кроку симуляції;
- поведінку при великому опорі кочення;
- відсутність подальшого розгону після досягнення граничної швидкості двигуна.

## Специфікація Modbus-інтерфейсу

### Загальні параметри

- Транспорт: `Modbus TCP`
- TCP порт: `5020`
- `unit id` за замовчуванням: `1`

У поточній реалізації використовуються:
- `discrete inputs` для сигналізації помилки;
- `holding register` для команди моменту;
- `input registers` для читання параметрів моделі.

Запис у `coils` і читання `coils` використовуються.

### Discrete Inputs

| Адреса | Назва | Тип доступу | Опис |
|---|---|---|---|
| `0` | `accelerator_sensor_failure` | читання | Прапорець помилки. Стає `1`, якщо через Modbus надійшла недопустима команда моменту. |

### Holding Registers

| Адреса | Назва | Тип доступу | Формат | Опис |
|---|---|---|---|---|
| `0` | `torque command` | читання/запис | `signed int16` | Команда моменту двигуна в Н·м. |

Особливості:
- допустимий діапазон визначається параметром `motor_max_torque_nm`;
- якщо записане значення виходить за межі допустимого діапазону, сервер:
  - не застосовує нову команду;
  - встановлює `discrete input 0 = 1`;
  - повертає помилку `illegal data value`.

### Input Registers

| Адреса | Назва параметра | Масштабування | Одиниці |
|---|---|---|---|
| `0` | `mass_kg` | `value = reg` | кг |
| `1` | `frontal_area_m2` | `value = reg / 1000` | м² |
| `2` | `rolling_resistance_coefficient` | `value = reg / 10000` | безрозмірна величина |
| `3` | `motor_max_speed_rad_per_sec` | `value = reg` | рад/с |
| `4` | `motor_max_torque_nm` | `value = reg` | Н·м |
| `5` | `gear_ratio` | `value = reg / 100` | безрозмірна величина |
| `6` | `wheel_radius_m` | `value = reg / 1000` | м |

Приклади:
- якщо в регістрі `1` зчитано `2200`, то фронтальна площа дорівнює `2.2 м²`;
- якщо в регістрі `5` зчитано `910`, то передатне число дорівнює `9.10`;
- якщо в регістрі `6` зчитано `310`, то радіус колеса дорівнює `0.310 м`.

### Початкові параметри моделі в програмі

У файлі `src/DriveSim.c` симулятор стартує з такими параметрами:

| Параметр | Значення |
|---|---|
| `mass_kg` | `1600.0` |
| `frontal_area_m2` | `2.2` |
| `rolling_resistance_coefficient` | `0.015` |
| `motor_max_speed_rad_per_sec` | `1200.0` |
| `motor_max_torque_nm` | `220.0` |

|---|---|
| `commanded_torque_nm` | `120.0` |

## Коротка логіка роботи програми

1. У `main()` створюється модель електромобіля і заповнюються її параметри.
2. Запускається потік симуляції, який викликає `Vehicle_step_50hz()` кожні `20 мс`.
3. Запускається потік моніторингу, який раз на секунду друкує швидкість у консоль.
4. Створюється `Modbus TCP` сервер.
5. Клієнт може:
   - читати параметри моделі;
   - читати поточну команду моменту;
   - записувати нову команду моменту;
   - отримувати сигнал про помилкову команду.
